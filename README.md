# 可复用的刷题辅助系统框架

一个以“题目为入口、历史证据为依据、AI 讲解为输出”的本地刷题辅助系统框架。

它适合需要长期整理错题、作答过程和知识点证据的学习者，也适合希望自己掌握数据、规则和审批权的个人用户。它不是自动规划学习的教练，不会擅自决定你今天学什么、怎么学或什么时候复习。

## 它解决什么问题

刷题过程中，真正有价值的问题通常不是“这道题答案是多少”，而是：

- 我究竟在哪一步开始出错？
- 这是计算失误，还是概念、条件识别或方法选择出了问题？
- 我过去是否在相同或相邻知识点上犯过类似错误？
- 这次 AI 的判断是事实，还是仍然需要我确认的候选结论？

本框架把这些信息拆成可追踪的题目、作答、错误、知识点、掌握证据和审批记录。用户把当前题目交给 AI 后，AI 可以先读取相关的已确认历史，再针对当前作答进行解释；任何带推断性质的内容都先作为 `PROPOSED`，不直接改变正式学习数据。

## 工作方式

```text
提交题目、答案或解题过程
        |
        v
提取客观字段：科目、题目、作答、用时、提示、是否看答案
        |
        v
按科目只读检索 CONFIRMED 历史题目、作答和错误
        |
        v
定位当前作答中最早出现的偏差
        |
        v
AI 先解决当前题目，再给出有证据支持的讲解
        |
        v
知识点、错因、掌握度和复习建议写成 PROPOSED
        |
        v
用户批准后，才进入正式数据库和 Markdown 记录
```

## 主要能力

### 1. 题目与作答档案

使用 Markdown/TXT 保存题目正文、标准答案、用户作答和详细分析；SQLite 保存 ID、关系、状态、时间、用时、提示次数和是否独立完成等结构化字段。

### 2. 按科目隔离

`config/subjects.json` 定义科目 ID、显示名称、目录和别名。检索器会同时检查数据库中的 `subject_id` 和文件目录，避免把不同科目的历史证据混在一起。

### 3. 可解释的历史检索

`09_数据库/question_retrieval.py` 支持按科目、知识点、关键词、公式文本和已确认错误检索。结果会显示命中原因、文本状态、历史作答数量、错误数量和证据状态，而不是只给一个不可解释的相似度分数。

### 4. 审批式数据治理

掌握度、错误根因、知识点关系、复习日期和长期计划等推断不能直接写入正式数据，必须遵循：

```text
proposal → 用户审核 → approvals → 事务内正式修改 → change_log
```

### 5. 本地可控

数据库在本地生成，代码和规则可以阅读、修改和审计。框架不依赖云端数据库，不强制绑定某个 AI 服务，也不把个人学习记录上传到仓库。

## 优点

| 优点 | 具体价值 |
| --- | --- |
| 隐私边界清晰 | 个人数据库、真实题目和作答可以只留在本机；公开仓库只放框架、模板和合成测试数据。 |
| 结果可解释 | 检索结果会给出知识点、错误、命中原因和证据状态，便于复核 AI 是否引用了正确资料。 |
| 不把推断当事实 | `CONFIRMED`、`PROPOSED`、`PENDING` 等状态分离事实和候选判断，减少 AI 自动“替你下结论”的风险。 |
| 可以长期积累 | 题目、作答和错误通过稳定 ID 关联，历史记录不会只停留在聊天窗口里。 |
| 科目不易串线 | 文件路径和数据库字段双重隔离，数学、英语、政治或其他科目可以独立管理。 |
| 规则透明可改 | 系统规则是 Markdown，数据库结构是 SQL，用户可以根据自己的考试和习惯调整。 |
| 依赖较少 | 当前核心功能使用 Python 标准库和 SQLite，初始化后即可运行基础检索和测试。 |
| 可作为其他系统的底座 | 现有框架可以继续接入 Web 界面、桌面应用、移动端、语义检索或自动化导入，而不必先推翻数据模型。 |

## 当前缺点与限制

这些不是隐藏问题，而是当前版本明确留下的改进空间。

| 当前限制 | 使用时会遇到什么 | 后续可以怎样改进 |
| --- | --- | --- |
| 目前主要依赖 AI 读取框架 | 下载仓库后，它不会自己变成一个会对话的应用；还需要把规则、检索结果或相关文件交给 AI 使用。 | 增加统一的 AI 适配层、上下文生成命令和可选的本地 API，让不同模型能按同一协议调用。 |
| 没有图形界面 | 当前入口是文件夹、Markdown、Python 命令和 SQLite，非技术用户上手成本较高。 | 增加本地 Web UI 或桌面 UI，提供题目录入、错因确认、历史检索和审批页面。 |
| 目前以电脑本地使用为主 | 不能像手机 App 一样随时拍题、录入或查看历史；电脑和手机之间也没有同步。 | 增加移动端或响应式 Web 端，并设计端到端加密同步和离线冲突处理。 |
| 数据需要手动整理 | 题目、作答路径、错误描述和状态仍需要用户或 AI 按模板录入，不能自动识别所有内容。 | 增加导入向导、剪贴板导入、批量 CSV/JSON 导入和从题库文件夹建立索引的工具。 |
| 检索仍以关键词和结构化关系为主 | 同义表达、图片题、扫描 PDF 或复杂公式可能无法被当前检索器准确召回。 | 在有足够真实题目后评估 FTS5、公式解析、OCR 和语义检索，并为每项能力增加可回滚的评估方案。 |
| 没有内置 OCR 和 PDF/图片解析 | 图片题或扫描资料不能直接进入题目正文，需要先人工转录。 | 增加 OCR 和公式识别，但必须提供人工校对，并把识别结果标为候选而不是事实。 |
| 没有多用户权限系统 | 当前数据模型面向单个本地使用者，不适合作为在线多人服务直接部署。 | 增加用户认证、数据租户隔离、权限模型和审计日志，部署前重新评估隐私风险。 |
| 数据库迁移仍需人工管理 | schema 变化、旧数据升级和回滚目前不是一键完成的产品流程。 | 增加版本化迁移脚本、迁移前检查、干运行和明确的回滚方案。 |
| 没有主动同步和提醒 | 系统不会自动推送到期复习，也不会主动安排学习计划。 | 可以增加“用户明确开启后”的可选提醒模块，默认关闭，并保留审批和可解释性。 |
| AI 输出质量取决于模型和上下文 | 不同模型的解题质量、上下文长度和工具能力不同，框架不能保证每次诊断都正确。 | 增加答案审核、引用检查、回归题集和模型适配测试，不把模型输出直接视为正式学习事实。 |

## 适合谁

适合：

- 想把错题和作答过程长期沉淀下来的人；
- 希望 AI 结合自己的历史记录讲题，而不是只得到通用答案的人；
- 重视隐私、可审计性和人工确认的人；
- 愿意编辑配置文件或使用少量 Python 命令的人。

暂时不适合：

- 只想打开网页立刻开始刷题、完全不想管理文件的人；
- 需要多人在线协作、账号体系或云端同步的人；
- 需要自动拍照识题、自动批改和完整移动端体验的人。

## 快速开始

### 环境

- Python 3.10 或更高版本；
- Git（可选，用于克隆和更新仓库）；
- 一个能够读取本地文件并按规则调用脚本的 AI 工具。

### 下载与初始化

```powershell
git clone https://github.com/LinJianDong175/28_KaoYan_AI.git
cd 28_KaoYan_AI
python 09_数据库/init_db.py
```

初始化脚本会根据 `config/subjects.json` 创建本地 `09_数据库/learning_os.db`。该数据库已被 `.gitignore` 排除，不会因为普通 Git 操作上传。

### 配置自己的科目

编辑 `config/subjects.json`，修改科目 ID、显示名称、目录、别名、考试类型和状态。然后在 `04_题库与作答/`、`05_错误与复测/` 等目录下按科目保存自己的文件。

仓库中的数学、英语、政治和专业课只是示例路由，不代表任何人的最终考试科目。

### 运行检索

```powershell
python 09_数据库/question_retrieval.py --subject math1 --text "关键词" --format markdown
python 09_数据库/question_retrieval.py --subject math1 --knowledge-point KP-EXAMPLE-001 --error-only
```

没有历史数据时，系统会明确输出“暂无相关个人历史证据”，不会把空数据解释为“没学过”或“掌握薄弱”。

### 运行测试

```powershell
python -m unittest discover -s 11_报告 -p "test_*.py" -v
```

测试使用运行时生成的临时数据库和合成题目，不读取或修改你的正式数据库。

## 数据与安全边界

公开仓库不应包含：

- `*.db`、`*.sqlite*` 或其他正式数据库文件；
- 真实题目、真实答案、真实作答过程和学习记录；
- 身份证号、手机号、邮箱、密码、令牌、API 密钥或其他个人信息；
- 聊天附件、扫描资料、教材 PDF 或未经授权的第三方内容。

建议先用合成数据验证流程，再把正式数据放在本地工作区。公开仓库能保证的是框架边界，不是替使用者自动完成隐私审查。

## 未来路线

改进优先级建议如下：

1. 先做本地 Web UI 和一键上下文生成，降低“必须手动让 AI 读取文件”的门槛。
2. 再做题目/作答导入和更清晰的审批界面，减少日常整理成本。
3. 用真实、脱敏、获得授权的题目集评估 FTS5、公式检索、OCR 和语义检索，而不是先堆技术。
4. 最后再考虑移动端、加密同步、多用户和在线部署，这些功能会显著扩大安全和运维范围。
