# 可复用的刷题辅助系统框架

这是一个面向个人学习者的、可本地运行的刷题辅助系统框架。它围绕“提交题目或作答 → 检索已确认历史证据 → 定位可能的知识卡点 → 生成讲解和候选记录”工作，不主动替用户安排学习计划。

## 设计原则

- SQLite 保存状态、关系和可审计的事实；Markdown/TXT 保存题目、作答和详细说明。
- `CONFIRMED`、`PROPOSED`、`PENDING` 等状态分离事实与候选判断。
- 掌握度、错误根因、复习日期和知识点关系必须经过审批后写入正式数据。
- 检索按科目路由，禁止把不同科目的历史证据混在一起。
- 仓库只提供逻辑、模板和合成测试数据，不包含任何用户数据库或个人学习记录。

## 快速开始

```powershell
python 09_数据库/init_db.py
python 09_数据库/question_retrieval.py --subject math1 --text "关键词" --format markdown
python -m unittest discover -s 11_报告 -p "test_*.py" -v
```

首次使用前请编辑 `config/subjects.json`，将示例科目替换为自己的科目和目录；再按模板录入题目、作答和资料。数据库文件 `09_数据库/learning_os.db` 由初始化脚本在本地生成，并已被 Git 忽略。

## 目录

| 目录 | 用途 |
| --- | --- |
| `00_系统与规则/` | 状态、审批、回答和检索规则 |
| `04_题库与作答/` | 按科目保存题目与作答模板 |
| `09_数据库/` | SQLite schema、受控访问、检索和一致性检查 |
| `10_审批中心/` | 候选判断的审批材料 |
| `11_报告/` | 自动化测试 |
| `98_Skill测试区/` | 仅用于测试的合成题目 |

## 数据边界

不要提交 `*.db`、`*.sqlite*`、真实题目、真实作答、学习记录、附件或包含个人信息的文件。公开仓库只应包含框架和脱敏示例。
