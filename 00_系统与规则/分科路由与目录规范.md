# 分科路由与目录规范

## 目的

配置文件中的每个科目，其题目、作答、错误、复测、复习和资料都在文件层面分开，在数据库层面通过 `subject_id` 分开，在回答层面只读取当前科目的个人历史。

## canonical 路由

| subject_id | 名称 | 固定目录 | 当前状态 |
|------------|------|----------|----------|
| `math1` | 数学一（示例） | `数学一` | PROVISIONAL |
| `english1` | 英语一（示例） | `英语一` | PROVISIONAL |
| `politics` | 思想政治理论（示例） | `思想政治理论` | PROVISIONAL |
| `major_pending` | 专业课（示例占位） | `专业课_待确定` | PENDING |

系统只接受配置中的 ID 或已登记别名，别名仅用于路由，不改变数据库正式名称和状态。仓库中的科目表仅作示例，使用者应编辑 `config/subjects.json`。

## 目录布局

```text
04_题库与作答/<科目>/题目/
04_题库与作答/<科目>/作答/
05_错误与复测/<科目>/
06_复习队列/<科目>/
07_资料库/<科目>/
```

`02_知识地图/<科目>/` 和 `03_学习记录/每日/<科目>/` 也遵守相同目录名。根目录模板、测试区和只读参考目录不属于正式科目资料。

## 隔离规则

1. 所有题目查询必须使用一个 canonical `subject_id`；未知 ID 或未登记别名直接报错。
2. SQL 查询同时按题目科目、确认状态和知识点科目过滤。
3. 题目正文路径若在另一科目目录中，标记 `wrong_subject`，不读取正文；路径不在科目目录、缺失或格式不支持时也不作为正式题目文本。
4. 测试数据库可以读取 `98_Skill测试区/` 合成题目，但测试数据不进入正式科目资料。
5. `major_pending` 仅表示专业课占位，不代表具体学校、专业代码或考试科目已确认。
6. 默认禁止跨科检索；只有用户明确要求跨科比较时，才另行生成跨科报告，不改变单科上下文。

## 记录方式

数据库记录的 `subject_id` 是正式归属；文件目录是可读的人工路由。两者冲突时不自动选择覆盖哪一边，应生成一致性问题或 proposal。新题目先进入对应科目目录，再登记 `questions.question_text_path` 和 `attempts.my_answer_path`。
