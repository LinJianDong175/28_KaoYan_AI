# 题目与知识点检索规则

## 1. 定位

检索层在用户提交错题、不会做的题或要求核对解法时按需运行。它负责寻找相关个人历史证据，不主动安排学习或复习，也不替代对当前题目的独立分析。

v1 使用现有 SQLite 关系和数据库明确引用的 Markdown/TXT 文件，不建立持久化全文索引、向量数据库或 OCR 管线。

## 2. 正式来源

- SQLite：题目 ID、知识点关系、作答事实、错误状态和证据状态；
- Markdown/TXT：题目正文、用户答案和标准答案正文；
- `question_id`、`knowledge_point_id`、`attempt_id`、`error_id` 和文件路径用于关联。

仅 `CONFIRMED` 记录可以进入正式检索结果和个性化讲解依据。`PROPOSED` 只显示为待审核提醒，排序权重为 0。

## 3. 允许输入

- 必填：`subject_id`；
- 可选：已确认的 `knowledge_point_id`；
- 可选：当前题目的关键词、公式文本或题型描述；
- 可选：只看带已确认错误的题目；
- 可选：结果数量，范围 1-100。

候选知识点尚未确认时，不得把它作为正式过滤条件。可以用题目文本先召回候选题，再生成知识点关联 proposal。

## 4. 文件读取边界

检索器只读取 `questions.question_text_path` 明确引用的 `.md` 或 `.txt` 文件，并执行以下检查：

1. 文件必须位于当前工作区内；
2. 排除配置中明确标记为参考资料的目录；
3. 不读取 `.db`、图片、PDF、Office 文件或其他二进制内容；
4. 单个文本文件不得超过 2 MiB；
5. 文件缺失、越界、格式不支持或编码错误时，返回状态，不中断其他结果；
6. 不递归扫描目录，不把测试数据库或正式数据库当作题目文本。

## 5. 召回和排序

v1 分数只用于结果排序，不代表掌握度、题目难度或错误概率：

| 信号 | 分数 | 说明 |
|------|------|------|
| 相同 CONFIRMED 知识点 | +100 | 只接受已确认关联 |
| 存在未解决 CONFIRMED 错误 | +40 | 多个错误不重复叠加该项 |
| 仅存在已解决 CONFIRMED 错误 | +15 | 不得称为当前未解决问题 |
| 完整文本或去空白公式命中 | +30 | 题目、知识点名或错误描述参与匹配 |
| 关键词命中 | 每个 +5，最高 +20 | 支持中文连续文本和英文/数字标记 |
| 最近作答 | 仅同分排序 | 不增加相关性分数 |

当仅输入文本且没有任何文本信号时，不返回同科目但无关的题目。当指定 CONFIRMED 知识点时，即使题面措辞不同，也可以返回该知识点上的历史题目。

## 6. 输出解释

每条正式结果必须包含：

- 题目 ID 和题目路径；
- 文本读取状态；
- CONFIRMED 知识点；
- CONFIRMED 作答和错误数量；
- 排序分数和可解释的命中原因；
- `evidence_status=CONFIRMED`。

`PROPOSED` 提醒单独输出，并明确标记“不作为事实”。无正式结果时输出“暂无相关个人历史证据”。

## 7. 使用方式

正式库只读检索：

```powershell
python 09_数据库/question_retrieval.py --subject math1 --text "关键词"
```

按已确认知识点检索：

```powershell
python 09_数据库/question_retrieval.py --subject math1 --knowledge-point KP-EXAMPLE-001 --error-only
```

测试库检索：

```powershell
python 09_数据库/question_retrieval.py --subject math1 --text "关键词" --db 98_Skill测试区/临时/test.db --format json
```

脚本只向标准输出返回 Markdown 或 JSON，不自动创建报告文件。

## 8. 升级条件

- CONFIRMED 题目约 500 道，或逐文件检索稳定超过 1 秒：评估 SQLite FTS5；
- 真实题目显示关键词无法覆盖同义表达：使用已积累题目集评估语义检索；
- 图片题目成为主要输入且人工转录成为实际瓶颈：评估 OCR 和公式结构识别。

任何持久化索引、批量处理、联网模型、数据库结构修改或新数据库文件，都必须另行提交影响、回滚和测试方案并等待批准。
