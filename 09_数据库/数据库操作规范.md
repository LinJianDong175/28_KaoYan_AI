# 数据库操作规范

## 统一入口

所有正式数据库写入必须通过 `db_access.py` 中的受控入口执行：

```python
from db_access import get_reader, get_writer, TransactionError
```

## 只读查询

```python
with get_reader() as (conn, cur):
    cur.execute('SELECT ...')
    rows = cur.fetchall()
```

## 写入（事务内）

```python
with get_writer() as (conn, cur):
    cur.execute('INSERT INTO ... VALUES (?)', (val,))
    # 退出时自动检查 foreign_key_check + quick_check
    # 检查失败自动 ROLLBACK
```

## PRAGMA 自动设置

每次连接自动执行：
- `PRAGMA foreign_keys = ON`
- `PRAGMA busy_timeout = 5000`

## 禁止事项

- ❌ 使用临时的随意 SQL 脚本直接修改正式数据库
- ❌ 在事务外调用 conn.commit()
- ❌ 手动执行 conn.execute('BEGIN') 而不使用 get_writer()
- ❌ 在连接中设置 PRAGMA foreign_keys = OFF
- ❌ 执行删除或重建数据库的操作
- ❌ 执行 DROP TABLE 或 DROP DATABASE
- ❌ 创建数据库副本或快照
- ❌ 执行任何备份操作

## 异常处理

事务失败时：
1. 自动 ROLLBACK
2. 生成异常报告到 `99_维护与检查/异常记录/`
3. 提交待审核修复方案
4. 不得自行删除或重建数据库

## 测试库用法

测试数据只允许存在于 `98_Skill测试区/learning_os_test.db`，不得写入正式库：

```bash
# 检查测试库完整性
python db_integrity_check.py --db ../98_Skill测试区/learning_os_test.db

# 检查测试库一致性（跳过 Markdown 对比，测试库与正式 Markdown 不共享状态）
python check_consistency.py --db ../98_Skill测试区/learning_os_test.db --skip-md
```

测试库操作同样必须走 db_access.py 受控入口（先覆盖 DB_PATH 指向测试库）。
测试结果不得改变正式学习上下文，不得影响用户真实掌握度和复习计划。

## 关键操作后检查

关键批量操作完成后应额外执行：
```sql
PRAGMA foreign_key_check;
PRAGMA quick_check;
```

检查失败则按上述异常处理流程执行。
